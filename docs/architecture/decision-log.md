| D-016 | The country (market) is always selectable by the user, also when imported data exists (an import only prefills it). | D-017 | Prospect simulator: estimate commissions from fictitious orders (products × quantity via the points table) and an optional fictitious team, as a separate mode of this app (same engine and UI), not a separate landing. | Proposed (direction) | 2026-11-16 | PF-06. After phase 1. Most sensitive case of the earnings-claims rule (BR-21): everything labelled as a fictitious example. Points tables per market: Q-15. |
| D-018 | **Import from RINGANA with the partner's own session.** The partner may log in with her RINGANA username and password inside the calculator to import her points (current or previous month). The password is used only for the login request and is never stored. The session token is kept only in `sessionStorage` of her browser (deleted when the tab closes) and a «forget my RINGANA session» button deletes it earlier. Only the two points services are used (`/teams/generations`, `/teams/revenue`); only numbers reach the form. Without a token, manual input works as today. | Accepted (direction) | 2026-11-17 | Prerequisites before building it: Q-17 (whether a server is needed), Q-18 (sample responses), Q-19 (RINGANA terms and privacy text). The calculator must run on its own origin (e.g. a subdomain linked from the team website), not embedded in WordPress, so no third-party script can read the token. If a server is needed it must be stateless and only forward the login and those two services (backend and hosting still undecided). |
| D-019 | One single-page app with three tabs — «Mi comisión actual», «Mi siguiente meta», «Ingeniería inversa» — sharing one copy of the real data. The active tab is reflected in the URL hash so back/forward and reload work without server configuration. | Accepted | 2026-11-17 | Design: `docs/architecture/three-tabs-design.md`. |
| D-020 | Each leg (direct partner) has a stable ID, an optional first name chosen by the partner (default «Pata N») and her VE. Names stay in the browser tab and never reach the engine. | Accepted | 2026-11-17 | PO: «un nombre de pila sin más». |
| D-021 | Reverse engineering offers three scenarios (own CT only — exact minimum; balanced own + team — proposal; more team — proposal) and a manual own-CT control, built with allocation strategies, binary search and non-dominated selection. Extra team points are assumed in generation 1 of each leg. | Accepted (design) | 2026-11-17 | Design §5; implemented in the next PRs. Supersedes the team route of PR #5. |
